# Как учебные материалы превращены в портфолио‑кейс

## 1. Основы анализа и проектирования баз данных

В исходных материалах были:

- описание предметной области интернет‑провайдера;
- выделение объектов, сущностей и атрибутов;
- анализ входных данных;
- определение первичных и суррогатных ключей;
- нормализация до 2НФ и 3НФ;
- матрица связей;
- инфологические и даталогические ERD‑диаграммы;
- словарь данных;
- табличные приложения для этапов проектирования.

Как это отражено в репозитории:

- предметная область описана в `docs/requirements-analysis.md`;
- нормализованная модель собрана в SQL‑схему с единым `snake_case` стилем;
- словарь данных переписан в `docs/data-dictionary.md`;
- диаграммы представлены в GitHub‑friendly Mermaid формате.

## 2. СУБД PostgreSQL / MySQL

В исходных материалах были:

- задания по настройке PostgreSQL и MySQL;
- матрицы ролей и прав доступа;
- SQL‑структура таблиц;
- индексы;
- хранимые процедуры;
- примеры заполнения и запросов;
- views и functions;
- сопровождение структуры БД.

Как это отражено в репозитории:

- PostgreSQL‑скрипты разделены по назначению в `sql/postgresql`;
- добавлена MySQL‑совместимая схема в `sql/mysql`;
- RBAC приведён к понятным публичным ролям;
- демо‑данные переписаны и обезличены;
- SQL‑файлы разложены по ответственности: schema, seed, indexes, views, functions, procedures, permissions.

## 3. Сборка полнофункциональных приложений

В исходных материалах были:

- цели программного продукта;
- группы пользователей;
- функциональные требования;
- пользовательские функции;
- ERD приложения;
- входные и выходные данные;
- блок‑схемы бизнес‑процессов;
- сравнение паттернов проектирования;
- структурная и архитектурная схемы;
- технические требования для desktop, web, mobile, application server и PostgreSQL;
- правила валидации и целостности данных.

Как это отражено в репозитории:

- архитектура приложения описана в `docs/system-architecture.md`;
- правила валидации собраны в `docs/validation-rules.md`;
- пользовательские сценарии представлены в `diagrams/user-flows.mmd`.

## Решение для публичной версии

Исходные `.docx`, `.xlsx` и `.drawio` файлы не включены, потому что они ориентированы на учебную сдачу, а не на работодателя.

Публичная версия содержит инженерный результат:

- чистые SQL‑скрипты;
- документацию по модели данных;
- нормализованную структуру БД;
- Mermaid‑диаграммы;
- Docker‑запуск PostgreSQL;
- безопасный синтетический набор данных.
